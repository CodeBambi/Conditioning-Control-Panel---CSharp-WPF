# API notes

Where the engine differs from REMIX-SPEC.md, one line each. Everything the spec
lists is present with the name and shape it gives; the rest is additions.

## Deviations

- `render(ctx, src, block, t, env)` - the spec writes `render(ctx, frameCtx, block, progress)`. `src` is a canvas holding the frame so far (null for `tint` and `spiral`, which never read it back), and `t` is raw progress 0..1: the eased 3 frame ramp is `env.ramp`, kept separate so an effect can ease its own way in.
- Effects may also export `clip(block, env)` and `bleeds`. Drain `spread` uses them to widen its clip past the tile.
- `env` also carries `strips` (every distinct media on the canvas that has frames, in tile order) and `underMedia` (the media under a tile target, null on canvas). Glitch `ghost` borrows a loop from them.
- `rectsFor` is overloaded. `rectsFor(n, orientation)` is still the fixed table (an array of rects); `rectsFor(tree, bounds, gap)` walks a split tree (an array of `{ id, rect }`). The table form is also exported plainly as `tableRects(n, orientation)`.
- A slot from `layoutAtFrame` is `{ tileIndex, rect, frameOffset }` plus, for a motion layout, any of `alpha` (0..1), `rot` (radians about the slot centre), `scale` (about the centre), `z` (draw order, stable by slot order within a z), `crop` (`{ cx, cy, z }`, pans and zooms inside the cover fit), `gap` (`false` skips the mosaic gutters) and `plate` (a ground border behind the tile, so a card reads as a card). The motion modules write the pitch's short names and `slotsFrom` in `layouts/index.js` spells them out: `g` -> `tileIndex`, `a` -> `alpha`, `sc` -> `scale`, `ph` -> the existing `frameOffset`; `rot`, `z`, `crop`, `gap` and `plate` keep their names. With none of them present the compositor draws exactly the tile it always drew.
- The layout registry entry grew `maxTiles` and `cost` (`cheap` | `mid` | `dear`). A motion layout is a module in `engine/layouts/` exporting `{ id, name, minTiles, maxTiles, cost, rectsAt(cfg, frame) }`, listed in `MOTION_LAYOUTS` (`layouts/index.js`) and merged into `LAYOUTS` by `layout.js`. `cfg` is `{ n, frames, stageFrames, seed, orientation, w, h }` from `motionCfg`, `rectsAt` is pure and deterministic from it, and the list at frame `frames` must draw the same picture as the list at frame 0. Motion layouts read the fixed table, not the dock tree.
- `layout.flip` (boolean, default false) is state on the layout, set through `setLayout({ flip })` and carried by `toJSON`/`fromJSON`; layout JSON without it loads as false. `layoutAtFrame` applies it once, after the mode has produced its slots, by mapping `flipSlot` over them, so `rectsAtFrame` and every mode including the motion layouts agree for free. `flipSlot` mirrors the rect across the canvas middle (`x' = 1 - x - w`), negates `rot` and turns `crop.cx` over; `alpha`, `scale`, `z`, `gap` and `plate` read the same either way and the tile pictures are never mirrored. The roll does not touch it.
- `engine/rects.js` is new: the fixed stage table and the easings, split out of `layout.js` so `layouts/*` can import them without a cycle. `layout.js` re-exports every name, so nothing outside the folder changed.
- `layout.mode` has an extra internal value, `deck`: one tile at a time, full frame, cut every `deckHold` frames. The Flash Deck vibe uses it. It is not one of the four modes the layout picker offers.
- `setLayout` also takes `{ tree }`, and `layout.docked` says whether the tree came from a dock or is still the default.
- `swapTiles` / `dockTile` return the new tree; `previewDock` returns `[{ id, rect, px }]`, rect in fractions and px in output pixels, and changes nothing.
- `engine/fonts.js` is new: `BUNDLED_FONTS` (the four faces the room ships, `block` | `script` | `round` | `pixel`), `BUNDLED_KEYS`, `fontUrl(key)`, `fontsInUse(blocks)`, `fontLoaded(key)` and `ensureFonts(keys)`, which loads them with the `FontFace` API, caches per key and resolves `false` rather than rejecting, so a file that never arrives leaves the fallback in `FONTS` drawing. `project.fontsReady()` ensures whatever the timeline asks for; `exportGif`, `exportVideo` and `estimateSize` await it before the first frame, and an edit that brings a new face in repaints the preview once it lands.
- `colourFor(params, env, table)` takes the name table the block understands. Tint and spiral use the default, `TINT_COLOURS`; caption passes `CAPTION_COLOURS` (`blocks.js`), which is the same three plus `white` and `black`. `contrastTo(hex)` next to it hands back whichever of `GROUND` and `INK` reads against a colour, which is what picks the rim under a caption and the word on a flash plate.
- `addBlock` and `blockFor` force `target` to `canvas` for effect `caption`, whatever the caller asks for: a word inside one tile of a mosaic is too small to read (owner call, 2026-09-07). Every other effect takes the target it is given.
- `exportGif` takes `{ onProgress, discordSafe, maxBytes, shrink, onRung, signal }` as well as the `onProgress` the spec names; `exportVideo` takes `{ onProgress, loops, signal }`. An aborted `signal` rejects with `abortError()` (`name` is `AbortError`) at the next frame.
- Media carry `srcW`/`srcH`, the file's own size, next to `w`/`h`, which are the canvas the strip was drawn at. `pickOrientation` wants the first pair; the second is the same for every clip on a canvas.
- Media keep `file` (the Blob they came from) and no `bytes`: the spec's `File`/`ArrayBuffer` pair held the original twice. Strips are decoded to the canvas length, not 8 s; `setDuration` to a longer canvas re-decodes only the strips that hit the old cap and have more source to show (`clock.stripNeedsMore`), the same way `setOrientation` re-decodes everything. `clearHistory` lets go of buried clips' bitmaps.
- `node --test remix/test/` does not work on Node 24 (it reads the path as a module). Use `node --test "remix/test/*.test.mjs"`.
- The roll's patch carries `stageMs` inside `layout` (`{ layout: { mode, stageMs }, loop, blocks }`), the shape every other patch already has, not at the top level as the first draft of the Auto section wrote it (now folded into REMIX-SPEC.md). `roll(seed)` takes a number, a `CCP-XXXX` code string, or nothing (a fresh random seed).
- A roll keeps any caption block on the canvas and replaces every other block. The Caption step owns the word; a reroll never loses it.

## Additions

- Project: `roll(seed?)` (the Auto page's button: `autoCompose` applied as one undo step, returns the new code), `rollBack()` / `rollForward()` (walk the roll history, return the code or null), `canRollBack`, `canRollForward`, `rollHistory` (`{ index, entries: [{ seed, code }] }`, at most `ROLL_CAP` = 20, a new roll after going back drops what was ahead), `mediaById(id)`, `adoptMedia(m)` (used by `fromJSON`), `blockFor(effect, target)` (find or make), `setCaptionText(s)`, `setCode(code)`, `drawFrame(i, ctx, w, h)` (draw at any size, for thumbs), `step(n)`, `filename(ext)`, `dispose()`, and the getters `orientation`, `seed`, `captionText`, `stampCorner`, `vibes`, `effects`.
- Project: `fontsReady()`, the promise every bundled caption face on the timeline is loaded (or gave up); the export path awaits it.
- Project: `setDiscordSafe(on)` and the `discordSafe` getter. It was a variable inside the export sheet; it is project state now, in `toJSON` / `fromJSON` and on the undo stack, because the roll reads it (a `dear` layout rolls at half weight when it is on).
- Module: `MOTION_LAYOUTS`, `motionLayout(id)`, `motionCfg(o)`, `slotsFrom(rects, n)`, `exitRect`, `stageAtFrame`, `easeInOut`, `seedRect`.
- Module: `pickOrientation(w, h)` (the canvas shape the Auto page takes from the first decoded file: over 1.2 landscape, under 0.83 portrait, else square), `autoCompose(state, seed)`, `AUTO_WEIGHTS` (the whole tuning surface of the roll), `passesGate`, `coverageOf`, `longestClean`, `LAYOUTS` (the layout registry `[{ id, name, minTiles, maxTiles, cost }]`; a new layout takes a row there and the roll and `LAYOUT_MODES` pick it up), `ROLL_CAP`, `Renderer`, `GROUND`, `OUTPUT_SIZES`, `sizeFor`, `kindForFile`, `UNSUPPORTED`, `stopDecoder`, `stopEncoder`, `CORNERS`, `nextCorner`, `stampRect`, `DISCORD_CAP`, `DISCORD_SAFE`, `LADDER`, `videoMimeType`, `canRecordVideo`, `abortError`, `UNDO_CAP`, `LOOPS`, `LAYOUT_MODES`, `PLAY_MODES`, `DURATIONS`, `FPS`, plus the layout tree helpers (`defaultTree`, `treeRects`, `pruneTree`, `ensureTree`, `dockInTree`, `swapInTree`, `leavesOf`, `isLeaf`, `adjacencyFromRects`, `DOCK_SIDES`, `MAX_TILES`, `GAP_PX`).

## The pool (2026-09-08)

- Module `pool.js`: `pickSet({ pool, pins, count, seed })` says which ids go on the canvas for a roll: pins first in pin order, then a seeded draw from the rest up to `count`; a pool that fits goes on whole, in pool order. `defaultCount(poolSize, pinned)`, `clampCountFor(count, poolSize, pinned)` (never under the pins, never over the pool or eight), `sameSet`, `POOL_CAP` = 100. The engine never holds the pool: the UI keeps files, thumbs and pins and hands ids over.
- Project: `probeMedia(file)` is the cheap look the pool takes at a file (one frame at `PROBE_SIZE` 144 square, kind, source size, frame count) with no strip, so a hundred of them cost what one decoded clip does. `hasMedia(id)` is true when the clip is in the list or the graveyard. `setMediaSet(ids)` puts exactly these clips on the canvas in this order: listed clips stay decoded, graveyard clips come back, ids the project does not hold are skipped (decode them first with `addMedia(file, { id })`), everything else goes to the graveyard; tiles follow, kept where the clip already had one. No commit of its own.
- Roll entries carry `set` (the media ids the roll was rolled on); `rollBack` / `rollForward` put that set back before the patch, and `rollHistory` entries and `peekRoll(steps)` (-1 back, +1 forward, no move) expose it so the UI can decode what the graveyard let go before it walks.

## UI asks, all in

What the UI wanted beyond the spec. Each is present, so the UI's `typeof` guards never fall through.

- `rectsAt(frame)` gives the tile rects at any frame, so the DOM tile hits follow grow, shuffle and deck stages.
- `setShrink(level)` and the `shrink` getter drive the one-tap shrink button; `exportGif({ shrink: true })` runs the ladder on save.
- `on('history')` fires after commit, undo and redo; `on('play', playing)` fires when playback stops by itself.
- `undo()` / `redo()` return the commit label or null, so the UI can toast "Undid drain".
- Readable `playing`, `frame`, `canUndo`, `canRedo`, `code`, `orientation`, `size`.
- `media.thumb` is a small canvas per item, for the strip, mini lane and filmstrip.
- Block params as the UI writes them: drain `strength`; tint `colour` (pink|lavender|gold|media) and `intensity`; spiral `strength`, `speed`; glitch `strength`, `pick` (which loop the seed borrows, null = from the seed) and `source` (`dice`, the default, or a media id that pins the ghost to that gif for good; an id no longer in the strip falls back to the dice, and glitch params without `source` read as `dice`, so old projects render unchanged); caption `text`, `font` (display|mono|hand|block|script|round|pixel), `colour` (pink|lavender|gold|white|black|custom), `glow`, `size`, `pos`; focus `radius`, `path`.
- Sample loops live in `remix/assets/sample/*.gif` (`make-samples.mjs` regenerates them); the UI loads them under the empty prompt.
