## 1. Method

Fixed at `plan.md` before any mapping, committed at `88599cd2c`, revised once at the plan gate
(`4327cb11f`) and still before any mapping. The universe was the repository root walked recursively,
with U1–U5 as ROLES over that one walk and exclusions restricted to generated bytes.

**The walk is a committed artefact, not a promise** (`walk.mjs`). SP-125's plan forbade
hand-assembled file lists and then contained one, because the author who writes the promise is the
author who then writes the list. So: the script's only positional argument is a ROOT DIRECTORY (no
file-list parameter exists), its only exclusions are a frozen generated-bytes constant (no
`--exclude` flag exists, so no source file can be dropped by name), it prints that exclusion set on
every run, it records every symlink it declines to follow, and it cross-checks each walk against
`git ls-files` and reports disagreements rather than reconciling them. Every count in the census
names the invocation that produced it.

## 5. The `honor_roll` normalisation pin

**Upstream** `Services/Quiz/IntakeHostService.cs:427-429` and **port**
`client/src/CcpClient.Desktop/Features/Intake/IntakeQuizRun.cs:153-154` are
`run.Niche.Trim().ToLowerInvariant()` with the `IntakeNiche.Fallback` whitespace arm. **MATCHES —
verbatim.** The board row is right that the call is load-bearing and right that this port has it.

**But the row locates it wrongly, and the real arrangement carries a latent defect.** The consumer
normalises nothing (`GamificationBridge.cs:602` adds `e.Category` raw) into a **default**
`HashSet<string>` (`AchievementProgress.cs:169`) — ordinal, case-sensitive. The two producers of that
one deliberately source-agnostic event disagree: the intake normalises, and
`QuizWindow.xaml.cs:542`'s `catDef?.Id ?? result.Category.ToString()` does not, its fallback being
the PascalCase enum (`QuizCategory.cs:6-13`). `"sissy"` and `"Sissy"` would be two entries against
`HonorRollCategories = 3`, so **`honor_roll` unlocks early, silently, and permanently** — the set is
persisted to `achievements.json`.

Bounded honestly: the classic launcher is `Visibility="Collapsed"`
(`GradedIntakeTabView.xaml:140`), so producer B is unreachable for a new user. This is a **latent
defect with a reachable construction** (both links in `_quizService?.CurrentCategoryDefinition` are
nullable), not a reproduced bug. Nothing was executed.

Recommendation as shape: normalise at the consumer or in the set's comparer, never at one of two
producers.

`ConditioningControlPanel/`, and every filesystem predicate lives in a helper — which is how
`FypCensusTests` already keeps itself out of the ledger, checked by reading it rather than assumed.
**Strictly stronger than the precedent:** the guard cannot pass without the reference tree at all.
The departure and its cause are stated in the test file's own summary, not only here.
