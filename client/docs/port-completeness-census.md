# Greenfield Client Completeness Census

## What this is

A **measured inventory of user-visible WPF behavior the greenfield client does not yet have**,
produced by sweeping the shipping product cluster by cluster and checking each behavior against
`client/src` and against `client/docs/task-board.md`.

It exists because the task board carried thirteen rows while the remaining work was two orders of
magnitude larger, and nothing in the repository said so. A queue that implies the port is nearly
finished is not a neutral omission: it is the exact failure the constitution's
reconcile-before-you-trust rule is written against.

## How to read it, and what it is not

- An entry here is **not** a commitment to port that behavior. It says the behavior exists
  upstream, is absent or partial here, and **no board row covers it**. Scope stays with the owner
  and belongs on the board, not in this file.
- `WPF surface size` is the **WPF** implementation measured with `wc -l`. It indicates the
  behavior's surface, **not** the port's cost: this port reproduces outcomes rather than files, and
  several of the largest entries are dominated by WPF markup and table data the port would never
  reproduce.
- Absence was proven by a recorded grep, not inferred from a missing filename. Where the client's
  own source already admits a thing is not ported, that admission is cited in preference to a grep.
- This census is **derived evidence, not authority**. The board is the only live queue. Where this
  file and the board disagree, the board wins and this file is the defect.
