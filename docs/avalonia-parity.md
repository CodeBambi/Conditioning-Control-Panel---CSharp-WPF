# Avalonia parity ledger

The single source of truth for "done" in the WPF -> Avalonia 12 port. One row per WPF window,
view, dialog, control, theme dictionary, shell partial and platform feature. The WPF head
(`ConditioningControlPanel/`) is the reference: a row is done when the Avalonia counterpart
matches it or is better, and is at least as fast.

Status, lowest to highest:
- `missing`: no Avalonia counterpart.
- `stub`: a counterpart exists but key behaviour is a placeholder, unwired or unavailable.
- `wired`: the counterpart implements the WPF behaviour as far as the source shows, and something in the
  Avalonia head opens or hosts it. Not yet proven. A surface nothing opens is `stub`, and so is one
  missing a WPF animation or motion effect.
- `verified`: proven on Linux by a headless test or render proof AND a Keincheck run on the live app
  (navigate, click, read state, screenshot), compared against the WPF reference. Evidence linked.
- `improved`: verified, and deliberately better than WPF; the reason is in avalonia-decisions.md.
- `blocked`: cannot progress yet; the blocker is in the notes. Revisit later.

`--render-all` (RenderProof) only proves a view draws; it never makes a row `verified` on its own.
Initial statuses were read from source on 2026-09-28 (stack tip #1765) and are not yet verified.

Starting totals (2026-09-28): 362 rows: 59 missing, 247 stub, 56 wired, 0 verified.

Notes carry what is stubbed or missing, platform-specific parts, existing evidence and, where it
matters, a performance note (startup, tab switch, list scroll, overlays, media).
